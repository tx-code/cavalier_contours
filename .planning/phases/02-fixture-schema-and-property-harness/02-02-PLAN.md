# Plan 02-02: Add Comparison Harness and Tolerance Policy

<objective>
Extend the existing property comparison utilities into a reusable fixture
harness. The harness should execute exact/approx fixture comparisons through a
central `run_fixture(&FixtureCase)` entry point and produce useful structured
failure output.
</objective>

<tasks>

<task>
<name>Add centralized tolerance policy</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_harness.rs`
- `cavalier_contours/tests/test_utils/pline_test_properties.rs`
</files>
<action>
Add a test-only `FixtureTolerance` or `TolerancePolicy` that preserves defaults
for property epsilon `1e-4`, position epsilon `1e-5`, and remove-redundant
epsilon `1e-4`, with per-fixture override support.
</action>
<verify>
Existing property helper behavior remains compatible.
</verify>
<done>
Fixture comparison code does not scatter raw epsilon values across tests.
</done>
</task>

<task>
<name>Add layered property comparison support</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_harness.rs`
- `cavalier_contours/tests/test_utils/pline_test_properties.rs`
</files>
<action>
Compare result count plus per-result vertex count, area, path length, and
extents by default; support opt-ins for orientation, open/closed, repeat
vertices, user data, and absolute-area comparison.
</action>
<verify>
Plan 02-03 seed tests can exercise default and abs-area/property options.
</verify>
<done>
Expected property sets cannot be empty for executable exact/approx fixtures.
</done>
</task>

<task>
<name>Implement generic fixture runner</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_harness.rs`
</files>
<action>
Implement a `run_fixture(&FixtureCase)` style API that dispatches offset,
boolean, and contains/properties operations, and skips/records non-executable
taxonomy modes.
</action>
<verify>
Plan 02-03 seed fixtures pass through the same runner.
</verify>
<done>
Runner is generic over fixture cases rather than requiring one ad hoc assertion
function per seed.
</done>
</task>

<task>
<name>Add structured failure output</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_harness.rs`
</files>
<action>
On assertion failure, include fixture id, source path/provenance, operation,
comparison mode, tolerance policy, actual properties, and expected properties.
</action>
<verify>
Failure message construction is visible in helper tests or assertion paths.
</verify>
<done>
Future mined cases can be diagnosed without hunting for source metadata
manually.
</done>
</task>

<task>
<name>Export harness test utilities</name>
<files>
- `cavalier_contours/tests/test_utils/mod.rs`
</files>
<action>
Add module and exports needed by `test_fixture_harness.rs`.
</action>
<verify>
`cargo test -p cavalier_contours --test test_fixture_harness` compiles.
</verify>
<done>
Harness remains test-only.
</done>
</task>

</tasks>

<must_haves>

- D-02: Reuse and extend `cavalier_contours/tests/test_utils/`.
- D-05: Keep harness code test-only.
- D-09: Prevent executable fixtures from asserting nothing.

- D-12: Add unified test-only tolerance policy/helper with existing defaults.

</must_haves>
