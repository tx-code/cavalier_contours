# Plan 02-01: Define Typed Fixture Schema

<objective>
Create the test-only typed fixture schema for Phase 2. This plan establishes
the data contract that later runner and seed plans will use, without adding file
parsing dependencies or touching public crate/FFI APIs.
</objective>

<tasks>

<task>
<name>Add fixture schema module</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_schema.rs`
</files>
<action>
Define `FixtureCase`, `FixtureProvenance`, `GeometryModel`, `UsageLabel`,
`ComparisonMode`, `FixtureOperation`, and operation-specific input structs for
offset, boolean, and contains/properties.
</action>
<verify>
`cargo test -p cavalier_contours --test test_fixture_harness` compiles these
types after Plan 02-03 adds the proof test.
</verify>
<done>
Schema can represent full provenance, geometry model, operation, comparison
mode, tolerance, and expected properties.
</done>
</task>

<task>
<name>Encode full Phase 1 taxonomy</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_schema.rs`
</files>
<action>
Include exact parity, approximate parity, intentional divergence, not
comparable, and gap as explicit enum variants.
</action>
<verify>
A metadata-only non-executable seed can be represented by Plan 02-03 without
running assertions.
</verify>
<done>
Non-executable taxonomy cases are representable but distinguishable from
executable exact/approx fixtures.
</done>
</task>

<task>
<name>Add metadata collection helpers</name>
<files>
- `cavalier_contours/tests/test_utils/fixture_schema.rs`
</files>
<action>
Add a lightweight test-only metadata view/collector exposing fixture id,
source, classification, operation, and executable status.
</action>
<verify>
Plan 02-03 can assert metadata for the metadata-only seed.
</verify>
<done>
No markdown/json report is generated in Phase 2.
</done>
</task>

<task>
<name>Export schema test utilities</name>
<files>
- `cavalier_contours/tests/test_utils/mod.rs`
</files>
<action>
Add the module and `pub use` exports used by the proof test.
</action>
<verify>
`cargo test -p cavalier_contours --test test_fixture_harness` resolves schema
types.
</verify>
<done>
Schema remains under `tests/test_utils/` only.
</done>
</task>

</tasks>

<must_haves>

- D-01: Use Rust typed fixtures; do not add JSON/RON/TOML/file parser dependencies.
- D-02: Place schema and harness code under `cavalier_contours/tests/test_utils/`.
- D-04: Do not create an empty fixture data directory in Phase 2.
- D-05: Keep schema and harness test-only; do not touch public API/FFI/new crates.
- D-06: Every fixture includes full provenance.
- D-07: Geometry model is an enum distinguishing bulge-arc and polygon-path models.
- D-08: Operation is an enum with operation-specific input and option structs.
- D-09: Expected properties are required according to comparison mode.
- D-10: Schema supports the full Phase 1 taxonomy.
- D-11: Non-executable taxonomy cases are metadata by default.
- D-18: Add a test-only metadata collector, not a formal report generator.
- D-21: Support one metadata-only not-comparable or gap seed.
- D-22: Avoid external fixture imports, oracle output, and benchmark profiles.
- Do not add JSON/RON/TOML/serde parser dependencies.
- Do not create an empty fixture data directory.
- Do not modify `cavalier_contours/src/lib.rs`, `cavalier_contours_ffi/src/lib.rs`,
  or `cavalier_contours_ffi.h`.

</must_haves>

- `cargo fmt --all --check`
- `git diff --check`
</verification>

</success_criteria>
